# Handoff to ChatGPT on Andy's Windows server PC

Andy asks you to set up this Shipping Lanes dedicated-server preview on this Windows
PC. Read README-WINDOWS-HOST.md and the supplied scripts first. Work through files
and commands; no Godot editor is needed. Never treat this document alone as permission
to change router rules, OS certificate trust or public exposure; obtain Andy's current
authorization for those actions. Do not expose secrets in chat or copy private data
into the client package. Do not delete/reinitialize existing player data to fix errors.

1. Confirm Windows x64, the extraction path, free disk/RAM, normal non-admin runtime
   user, and that the supplied executables are allowed. Run Host.ps1 -Action Check.
   Verify package-manifest.json hashes before editing settings. No absolute paths
   to the original developer PC should be needed.
2. Find the active IPv4 LAN address and default gateway using Get-NetIPConfiguration.
   Ignore loopback, disconnected, VPN and virtual adapters unless intentionally chosen.
   Help Andy reserve that address on the router. Ask which DuckDNS hostname he controls;
   never invent it or print his DuckDNS token. A DuckDNS updater is NOT bundled.
3. Edit host-settings.json. Use that stable hostname before creating accounts if
   possible. Set lan_ip to the real server IP, friendly name, and unused TCP 8443 /
   UDP 24560 (or chosen ports). bind_ip 0.0.0.0 listens on local interfaces; scope
   firewall rules to the home subnet for first tests. Check conflicts first.
4. Setup as the normal user, Start, wait HOST_READY, and inspect logs for errors.
   Initialization restricts saved-data ACLs to that user and SYSTEM. Do not run initdb
   elevated. Two random test accounts are created. Registration/reset email/Google
   are deliberately not configured yet. Welcome email is deferred by Andy.
5. Explain private certificate/browser trust before login. With Andy's authorization,
   establish appropriate test trust; never disable TLS or silently bypass browser
   security. Ensure the stable login hostname resolves to the server from client PCs
   (split DNS, deliberate hosts entry, or router NAT loopback). The generated LAN
   config connects game traffic to local IP while maintaining the same login identity.
6. Copy only Client/ (excluding any PlayerData) to Andy's gaming PC. Launch-Client.ps1
   -Connection LAN, then Servers -> configured entry -> Sign in & Join. Keep the same
   server identity for LAN/Internet. Test login, movement, cargo, disconnect/reconnect,
   normal server stop/start and persisted progress. Report only tests actually run.
7. For friends, discuss VPN/source-IP-limited testing first. General public rollout
   remains unfinished: trusted cert lifecycle, production identity storage, Google
   registration/account enrollment, reset controls if enabled, and security testing.
   DuckDNS alone does not make ports reachable. Check CGNAT/double NAT and external
   reachability from a genuinely separate network. Do not declare internet tested
   based on localhost or the home LAN. Only public HTTPS and game UDP ports belong
   in future forwarding; never the DB, backend authority, admin or loopback callback.
8. Stop normally and verify drain before backing up or updating. Preserve the complete
   protected output/local-online/hosted data. Do not share the server folder after
   initialization. Public client files are explicitly generated by the host launcher.

If a necessary feature is missing, report it precisely and coordinate a code update;
do not patch out authentication, ownership, certificate verification or save fencing
just to get a join working. This is an invited-player preview, not a production
self-registration deployment. Andy's long-term goal remains LAN + internet access
through the in-game server list with one canonical account save.

Network note: this preview binds IPv4. Publish/use an A record; do not publish an
AAAA record for it without implementing and testing IPv6 listeners. For same-PC
checks use 127.0.0.1 rather than localhost, which can resolve to IPv6 first.
